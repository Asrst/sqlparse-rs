# sqlparse-rs — Testing & Usefulness Proof Plan

### Companion to `docs/PLAN.md` · AngelHack "Building with IBM Bob"

A fast-but-untrusted parser is worthless. This plan defines the four proofs —
correctness, speed, safety, downstream integration — and the exact demo. Every
proof produces an artifact that lands in the repo and the deck.

**Status at time of writing (what is already banked):**

| Proof | State |
|-------|-------|
| 1 — Correctness | 24/24 differential records byte-identical (tokenize + split) vs real `sqlparse==0.6.0`; 26 Rust unit tests + 5 wrapper tests green. This plan *widens* the corpus. |
| 2 — Speed | Equal-work bench on 1.35 MB corpus: **~6.8x** (Python 0.777s vs Rust 0.114s, 103,800 tokens asserted equal on both sides). This plan adds realistic batch workloads. |
| 3 — Safety | Linear by construction (hand-written scanner, `#![forbid(unsafe_code)]`, no regex engine in the hot path). This plan *measures* it. |
| 4 — Downstream | Not yet exercised. This plan runs it. |

## Proof 1 — Correctness: differential harness (build FIRST — already standing, widen it)

**Claim to prove:** the Rust lexer emits byte-identical `(ttype, value)` token
streams to Python `sqlparse` 0.6.0 on every input we can throw at it, and
`split()` returns identical statement lists.

**Two-layer gate (both must be green; layer 1 is the inner loop, layer 2 the referee):**

1. **Rust gate** — `make check` (`cargo test -p sqlparse-core`): unit tests +
   differential test reading `corpus/inputs.bin` vs committed
   `corpus/goldens*.txt`. Goldens are generated by `tools/oracle.py` from the
   *real* installed sqlparse 0.6.0 and committed, so the gate runs anywhere.
   Golden headers carry input byte-counts + sha256 so stale-corpus drift is
   detected.
2. **Python gate** — `tests/test_parity.py`: for every file in `corpus/sql/`
   (and the fuzz set), compare live `sqlparse` vs live `sqlparse_rs`
   directly — no golden round-trip. Token types compared by dotted path
   (`str(ttype)`, e.g. `Token.Keyword.DML`), never object identity.
   Auto-writes `tests/parity-report.md`.

**Corpus** (`corpus/sql/*.sql`, one record per file):

1. **Trap micro-cases** — already standing: comments + hint variants
   (`--+`, `# +`), strings with `''`/`\'` escapes and unclosed-quote
   backtracking, numbers with regex-backtrack semantics (`1.5x` →
   `Float "1."` + `Name "5x"`), placeholders (`?`, `%(name)s`, `:name`,
   `$1`, `@name`), PG/JSON operators (`->>`, `#>>`, `@>`, `<@`, `?|`, `:=`),
   `[bracket]` vs `a[t2]` indexing, dollar quotes incl. `$$x$y$$` and
   unclosed, multiword keywords (`END IF`, `AT TIME ZONE`), BEGIN blocks,
   `GO`/`GO 2`, case-insensitive sweep, CRLF/CR/FF mixes, CJK/accents.
2. **NEW — Dialect keyword sweep** (`tools/gen_dialect_sweep.py`): one
   generated record per keyword dict — COMMON, ORACLE, MYSQL, PLPGSQL, HQL,
   MSACCESS, SNOWFLAKE, BIGQUERY — every keyword in Upper and lower form
   inside a minimal statement. Proves the 803-entry first-dict-wins table.
3. **NEW — Regression-targeted shapes** (named after upstream issues):
   `x BETWEEN .03 AND .06` (issue601 float-vs-member-access),
   `schema . name` spaced member access (issue39),
   `END IF` / `END LOOP` / `END CASE` protection, 500-deep nested parens,
   10,000-element `IN (...)` list, 10,000 unclosed `$tag$` openers,
   comment-only statements (`/* ... */` chains), backtick/´quoted´ names.
4. **NEW — Fuzz corpus** (`tools/gen_fuzz.py`): N=2,000 (seeded, default
   `--seed 1337`) statements assembled from fragment grammar fragments +
   random punctuation soup. Deterministic, so a diff is always reproducible.
   Any diff is minimized and promoted into `corpus/sql/` as a permanent
   regression record. Bob can regenerate with fresh seeds for the live demo;
   the gate must stay at zero.

**Gate: zero diffs.** Any single diff blocks the claim. No "close enough."

**Artifact:** `tests/parity-report.md` (auto-generated: corpus size, per-source
record counts, total tokens compared, diffs = 0) + committed goldens.

## Proof 2 — Speed: batch benchmarks (never single queries)

**Claim to prove:** order-of-magnitude throughput on the workloads where
sqlparse actually hurts. We openly concede median single-query formatting
gains are invisible (2 ms → 0.2 ms) — that honesty goes in the deck. Quote
measured numbers only; the 10–50x line is an aspiration, not a result.

**Workloads** (`benchmarks/bench.py`, all sizes tunable):

1. **Dump tokenize** — pg_dump-style file (generated: CREATE TABLEs + INSERT
   batches; default 25 MB, `--mb` to raise). Metric: MB/s + wall time,
   Python vs Rust.
2. **Dump split** — same file through `split()`. The migration/restore story.
   Metric: wall time.
3. **Query-log fingerprinting** — synthetic slow-log queries (default 200k,
   `--queries`) normalized via tokenize → literal-stripping → fingerprint.
   Metric: wall time; **plus correctness assertion**: fingerprint multisets
   must be identical across engines.
4. **Debug-toolbar freeze (honest, NOT a speedup claim)** — 10,000-element
   IN list through Python `format(reindent=True)` with cProfile: report the
   % of time inside tokenization. Tier 3 (`parse`/`format`) is deliberately
   not ported in this MVP, so this workload quantifies the headroom a Tier 3
   port would unlock instead of faking a number.

**Method:** warmed runs (1 warmup discarded), min-of-3, same machine, machine
specs printed. **Equal-work validation before any timing is reported:** token
count + sha256 stream checksum must match across engines, else the run is
void. `bench.py` prints a markdown table pasteable into the deck and writes
`benchmarks/results.csv`.

**Artifact:** `benchmarks/RESULTS.md` + raw `results.csv`.

## Proof 3 — Safety: linear-scaling plot (the deck's killer visual)

**Claim to prove:** the Rust lexer scales linearly on adversarial inputs *by
construction* — there is no backtracking engine left to go quadratic.

**Method** (`benchmarks/scaling.py`):
- Inputs: unclosed `$$` runs and comment-only statements at 1 KB → 10 KB →
  100 KB → 1 MB → 10 MB.
- Wall time vs size, Python vs Rust, log-log axes → `benchmarks/scaling.png`
  (+ `scaling.csv` raw).
- Per-size timeout guard (120 s): a Python point that exceeds it is recorded
  as DNF — and a DNF at 10 MB on the Python curve *is* the visual.

**Honesty note (deck, verbatim):** "sqlparse 0.6.0 already patched the four
ReDoS CVEs in Python (0.4.4–0.6.0). We do not claim to fix CVEs — we remove
the *architecture* that produced them: no regex engine remains in the hot
path, so this input class cannot regress." Expect Python 0.6.0 to scale
linearly-ish on these shapes too; the Rust curve stays flat *and* carries the
constant-factor gap, and the guarantee is structural, not patched-in.

**Artifact:** `benchmarks/scaling.png` + `scaling.csv`.

## Proof 4 — Downstream integration (the drop-in proof)

**Claim to prove:** "without disrupting core functionality" — unmodified
downstream code works against `sqlparse_rs`.

**Method:**
1. **Upstream suite, ported surface** — fetch the real test suite
   (`pip download sqlparse==0.6.0 --no-binary :all:` → sdist ships `tests/`).
   Run `tests/test_split.py` plus the tokenize-sensitive regression tests
   through an alias shim (`sys.modules["sqlparse"]` backed by `sqlparse_rs`
   for `tokenize`/`split`). Report honest pass/fail/skip counts per file;
   tests needing `parse`/`format` are skipped and counted, not fudged.
2. **One real downstream script, unmodified** — `examples/statement_report.py`
   (statement counting + fingerprinting over a mixed log) run twice —
   `DOWNSTREAM_ENGINE=sqlparse` vs `=sqlparse_rs` — outputs must be
   byte-identical. No source changes, only the env var.
3. `import sqlparse_rs as sqlparse; sqlparse.split(...)` smoke test in the demo.

**Artifact:** `tests/downstream-report.md`.

## The 30-second demo (exact script)

1. `python benchmarks/bench.py --mb 25` → side-by-side timers from
   RESULTS.md (equal-work asserted).
2. Show `benchmarks/scaling.png` — flat Rust line; Python bends or DNFs.
3. `import sqlparse_rs as sqlparse; sqlparse.split(dump)` — unmodified
   downstream code, correct output (Proof 4 evidence).
4. One-liner: *"Same API. Byte-identical output. Linear time by
   construction. The regex-backtracking class is gone."*

## Acceptance criteria (ship / no-ship)

- [ ] Parity: zero diffs on trap corpus + dialect sweep + regression shapes +
      2,000-record fuzz (Proof 1)
- [ ] Speed: measured, equal-work-asserted speedup on dump tokenize AND dump
      split — quote the table, not the aspiration (Proof 2)
- [ ] Safety: flat Rust scaling to 10 MB adversarial input; Python DNFs
      reported honestly if they occur (Proof 3)
- [ ] Downstream: upstream `test_split.py` pass rate reported as measured;
      downstream script byte-identical across engines (Proof 4)
- [ ] If any criterion fails, the deck reports it honestly and narrows the
      claim — a smaller true claim beats a bigger unproven one.
