## What was fixed

### Root cause of the CI failures

[`tests/test_independence.py`](tests/test_independence.py:29) spawns subprocesses with `{**os.environ}` as the environment. In GHA, after `maturin build --out dist/ && pip install dist/*.whl`, the `.so` lives in **site-packages** — not in `python/sqlparse_rs/`. So `_HAS_SRC_SO` is `False` and the test doesn't add `python/` to `PYTHONPATH`.

But the **parent pytest process** had `PYTHONPATH=python/` in its environment (inherited from earlier steps or the outer shell), which the subprocess inherited. Python then found `python/sqlparse_rs/__init__.py` on that path — but `sqlparse_rs.sqlparse_rs` (the `.so`) wasn't beside it → `ModuleNotFoundError`.

**Fix**: when `_HAS_SRC_SO` is `False` (wheel-install layout), explicitly `pop("PYTHONPATH")` from the subprocess env so only site-packages is searched.
