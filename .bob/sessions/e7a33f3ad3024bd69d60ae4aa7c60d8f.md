## Why use `uv` here?

`uv` is an Astral drop-in for `pip` + `venv` + `pip-tools`, written in Rust. For this project's CI it would give:

| Benefit | Concrete impact |
|---|---|
| **Speed** | `uv pip install` is 10–100× faster than `pip install` — relevant on every CI job that does `pip install maturin pytest sqlparse` |
| **Reliable venv** | `uv venv` creates a venv in one command; `maturin develop` then works because `VIRTUAL_ENV` is set by the `uv` action |
| **Lock-file reproducibility** | `uv.lock` pins every transitive dep; `sqlparse==0.6.0` is pinned by name today but transitive deps of `pytest`/`maturin` float |
| **Python version management** | `uv python install 3.12` — no need for `setup-python` in CI |

The `maturin develop` fix we just shipped (`maturin build + pip install`) is the correct minimal fix. But with `uv` the original `maturin develop` pattern *would have worked* because `uv venv` + `uv pip install` gives an active `VIRTUAL_ENV`.

---
